# レビュー方針

作業フローは [AGENTS.md](../AGENTS.md)、検証範囲は [テスト設計方針](testing-policy.md) に従う。

- `review-local-change` は未コミット差分や指定コミット、`review-feature-branch` は基準ブランチからの全差分と PR・CI の状態、`review-client-server-authority` は client 由来の入力を検証する。各スキルは読み取り専用で使う。
- 指摘は具体的な故障、到達条件、影響範囲、修正箇所に基づいて優先度を決める。未実行の検証や PR 説明の不足は確認状況として記録する。
- registry と EventBus への接続、専用サーバーのクラスロード、任意依存が不在の場合の経路、Gradle と配布 TOML の整合を確認する。
- client の入力で server 状態を変更する場合は、所有権、射程、コスト、変更対象、保護設定など、実際に server が守る制約を確認する。client と server 間で差を許容する設計では、受理と拒否の両方を検証する。
- 保存済みワールド、アイテム、プレイヤーデータと、それらが参照する ID を保護する。権限や禁止操作を管理する設定の変更では、旧設定が無視されて操作が意図せず有効にならないようにする。
- 翻訳キー、モデル・テクスチャ、レシピ・タグや一般設定の意図した変更は、利用者への主な影響を PR で説明する。保存済み資産の消失につながる変更には保存データの保護を適用する。
- 生成リソースの重複・旧出力と、外部素材の出典・ライセンス表示を確認する。
